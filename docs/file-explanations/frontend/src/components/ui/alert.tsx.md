# frontend/src/components/ui/alert.tsx

## Purpose

shadcn Alert components: `Alert`, `AlertTitle`, `AlertDescription`, `AlertAction`.

## Where It Fits

frontend/src/components/ui (generated by the shadcn CLI, then project-owned). Used by `StatusCard`, `SystemInfoCard` and `routes/login.tsx`.

## Walkthrough

`alertVariants = cva(base, { variants: { variant: { default, destructive } }, defaultVariants })`. `Alert` is a `div` with `role="alert"`, `data-slot="alert"` and `cn(alertVariants({variant}), className)`; the other parts add slot attributes used by `has-data-[slot=...]` selectors for layout. Imports `cn` from the `cn` package. The generator's physical utilities were converted to logical ones for RTL: `text-start`, `has-data-[slot=alert-action]:pe-18` and `end-2` (in `AlertAction`).

## Concepts Used

### Tailwind, shadcn/ui and variants

#### What it means

Tailwind composes styles from small utility classes. shadcn/ui copies component source into your repo; `cva` (class-variance-authority) maps variant props like `variant="outline"` to class strings.

#### How it works here

`alertVariants`.

#### Why it matters here

Variant props -> class strings.
