# .gitattributes

## Purpose

Forces Git to normalise text files to LF so Windows and Linux contributors do not create line-ending diffs.

## Where It Fits

Read by Git on checkout/commit. Complements `.editorconfig` (`end_of_line = lf`). The README gives PowerShell and bash commands, implying Windows contributors exist.

## Walkthrough

Single line `* text=auto eol=lf`: every file Git detects as text is stored with LF and checked out with LF (no CRLF conversion). Files Git detects as binary (none are tracked here) would be left untouched.

## Concepts Used

### Editor, line-ending and ignore configuration

#### What it means

Files such as `.editorconfig`, `.gitattributes` and `.gitignore` keep formatting, line endings and untracked files consistent across machines and operating systems.

(Full tutorial with execution traces: [PROJECT_OVERVIEW.md#5-startup--bootstrapping](../PROJECT_OVERVIEW.md#5-startup--bootstrapping).)

#### Where it appears in this file

The one rule.

#### How it works here

Git applies the attribute pattern `*` to every path.

#### Why it matters here

Shell scripts, YAML and JSON stay LF everywhere; avoids spurious `has-pending-model-changes` or formatting diffs.
