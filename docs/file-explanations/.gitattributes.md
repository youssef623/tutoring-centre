# .gitattributes

## Purpose

Forces Git to normalise text files to LF so Windows and Linux contributors do not create line-ending diffs, and pins the generated API artefacts to LF.

## Where It Fits

Read by Git on checkout/commit. Complements `.editorconfig` (`end_of_line = lf`). The README gives PowerShell and bash commands, implying Windows contributors exist. The two added lines protect the CI 'is up to date' checks.

## Walkthrough

Line 1 `* text=auto eol=lf`: every file Git detects as text is stored with LF and checked out with LF (no CRLF conversion). Line 2 `frontend/openapi/*.json text eol=lf` and line 3 `frontend/src/api/generated/** text eol=lf`: the committed OpenAPI document and the Orval output are always LF, so a Windows checkout does not make `git diff --exit-code -- frontend/openapi` or `-- src/api/generated` report a difference caused only by line endings. (The explicit lines repeat the general rule for those paths; the intent is stated by the CI steps, not by a comment in this file.)

## Concepts Used

### Editor, line-ending and ignore configuration

#### What it means

Files such as `.editorconfig`, `.gitattributes` and `.gitignore` keep formatting, line endings and untracked files consistent across machines and operating systems.

All three lines.
