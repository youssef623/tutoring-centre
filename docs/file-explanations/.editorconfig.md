# .editorconfig

## Purpose

Declares formatting and a few diagnostic rules that editors and the compiler apply consistently across the repository.

## Where It Fits

Read by IDEs (formatting), and by the .NET compiler for the `[*.cs]` and `[tests/**/*.cs]` sections (analyzer severities, including the migrations folder exemption). Applies to both the backend and `frontend/`.

## Walkthrough

- `root = true` stops the lookup from continuing above the repo.
- `[*]`: UTF-8, LF line endings, final newline, trim trailing whitespace, 4-space indent.
- `[*.{ts,tsx,js,jsx,mjs,cjs,json,yml,yaml,css,html}]`: 2 spaces. `[*.{csproj,props,targets,slnx,xml}]`: 2 spaces. `[*.md]`: 2 spaces and trailing whitespace is kept (Markdown uses two trailing spaces as a hard break).
- `[*.cs]`: `csharp_style_namespace_declarations = file_scoped:suggestion` (source uses `namespace X;`), `csharp_style_var_when_type_is_apparent = true:suggestion`, `csharp_using_directive_placement = outside_namespace:suggestion`, `dotnet_sort_system_directives_first = true`. All `:suggestion`, so never build errors (the comment says so).
- `[src/TutoringCentre.Infrastructure/Persistence/Migrations/*.cs]` (added): `dotnet_diagnostic.CA1861.severity = none` - EF Core generates these files verbatim and a composite-column array literal in a generated `CreateIndex` call trips CA1861 although migrations run once, never in a hot path; the comment says never hand-edit the folder - fix the entity configuration and regenerate.
- `[tests/**/*.cs]`: `dotnet_diagnostic.CA1707.severity = none` - test names like `SendAsync_ValidCommand_Persists` contain underscores, which CA1707 would flag; production code keeps the rule.
Because `TreatWarningsAsErrors` is on, raising a severity to `warning` here would break builds.

## Concepts Used

### Editor, line-ending and ignore configuration

#### What it means

Files such as `.editorconfig`, `.gitattributes` and `.gitignore` keep formatting, line endings and untracked files consistent across machines and operating systems.

(Full tutorial with execution traces: [PROJECT_OVERVIEW2.md#5-startup--bootstrapping](../PROJECT_OVERVIEW2.md#5-startup--bootstrapping).)

#### Where it appears in this file

Whole file.

#### How it works here

Editors apply the indentation/EOL rules while typing; the compiler reads the `CA1707` severity per file path.

#### Why it matters here

Prevents CRLF/LF churn and keeps the test-naming convention warning-free.

## Data and Control Flow

No runtime data flows through this file; it is consumed by tooling or readers, not executed by the application.

## Configuration and Environment

None.

## Gotchas and Issues

The 2-space rule for `.slnx` and `.props` matches the existing files; `.csproj` files under `src/` start with a UTF-8 BOM, which `charset = utf-8` does not require or remove.
