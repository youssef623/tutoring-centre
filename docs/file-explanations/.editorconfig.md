# .editorconfig

## Purpose
Repository-wide editor and code-style rules: encoding, line endings, indentation, a few C# style preferences, and one analyzer severity override for tests. IDEs and the .NET compiler/analyzers read it.

## Where it fits
Root config. It works together with `Directory.Build.props` (`TreatWarningsAsErrors`, `AnalysisLevel`) and the frontend's `.prettierrc`.

## Walkthrough
- **Line 2, `root = true`:** don't look for parent `.editorconfig` files.
- **Lines 4–10, `[*]`:** UTF-8, LF line endings, final newline, trim trailing whitespace, 4-space indent.
- **Lines 13–14:** 2-space indent for TS/JS/JSON/YAML/CSS/HTML.
- **Lines 17–18:** 2-space indent for MSBuild and solution files.
- **Lines 20–22:** Markdown uses 2-space indent and keeps trailing whitespace (two trailing spaces are a Markdown line break).
- **Lines 24–29, `[*.cs]`:** prefer file-scoped namespaces, `var` when the type is apparent, and `using` outside the namespace, all at `:suggestion` severity (IDE hints, never build errors); System usings sort first.
- **Lines 31–34, `[tests/**/*.cs]`:** `dotnet_diagnostic.CA1707.severity = none`. CA1707 forbids underscores in identifiers, which would break the `Method_Condition_Result` test naming. The rule stays on for `src/`.

## Concepts used
- **Analyzer severities:** because `TreatWarningsAsErrors` is on (`Directory.Build.props:7`), an analyzer warning breaks the build. This file can lower a rule's severity per path.

## Gotchas and issues
- Prettier (`frontend/.prettierrc`) is also configured but not enforced in CI. Several frontend files don't conform to it (`npx prettier --check .` flags 9).
- `.config/dotnet-tools.json` and `Directory.Packages.props` lack final newlines despite line 7.
