## Why four projects, not four folders in one project

Separate assemblies make the dependency rules compiler-enforced in one specific way: a circular reference between projects fails `dotnet restore`/`dotnet build` outright (see the `../tests/.semantic.md` section on the cycle experiment). Folders within a single project wouldn't give that guarantee — nothing would stop `Domain.cs` from calling into `Infrastructure.cs` if they shared an assembly.
