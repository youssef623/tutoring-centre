## `DependencyInjection.cs` — `AddInfrastructure(services, configuration)`
In order:
1. `AddSingleton(TimeProvider.System)`; `AddSingleton<IClock, SystemClock>()`.
2. `connectionString = configuration.GetConnectionString("Postgres")` — i.e. key `ConnectionStrings:Postgres`.
3. `services.AddHealthChecks()` then either `AddCheck("postgres", () => Unhealthy("ConnectionStrings:Postgres is not configured."), tags)` (blank string) or `AddNpgSql(connectionString, name: "postgres", tags: ["ready"])`. `ReadinessTags` is a `static readonly string[]` to avoid per-call allocation (analyzer CA1861).
4. `AddSingleton<TimestampInterceptor>()`.
5. Options: `AddOptions<DatabaseOptions>().Configure(o => o.ConnectionString = connectionString ?? "").ValidateDataAnnotations().ValidateOnStart()`.
6. `AddDbContext<AppDbContext>((sp, options) => options.UseNpgsql(sp.GetRequiredService<IOptions<DatabaseOptions>>().Value.ConnectionString, npgsql => npgsql.MigrationsHistoryTable("__ef_migrations_history", Schemas.Platform)).UseSnakeCaseNamingConvention().AddInterceptors(sp.GetRequiredService<TimestampInterceptor>()))`.
7. Scoped: `IUnitOfWork→UnitOfWork`, `ICentreRepository→CentreRepository`, `ISystemInfoReadService→SystemInfoReadService`.

Gotcha: the connection string is captured **when `AddInfrastructure` runs**, from the configuration as it exists at that moment. Test factories therefore set it with `UseSetting` (visible before build); a later configuration override would not reach it.

`public sealed class AppDbContext(DbContextOptions<AppDbContext> options) : DbContext(options)`; `OnModelCreating` → `ApplyConfigurationsFromAssembly(typeof(AppDbContext).Assembly)`. No `DbSet` properties. Public because `ReadOnlyQueryTests`/`TransactionBoundaryTests` inject it and migrations reference it.

### `Configurations/Centres/CentreConfiguration.cs`
Explained row by row in overview §6.9. Value-converter methods `LocaleToDatabase`/`LocaleFromDatabase` use `switch` expressions that **throw `ArgumentOutOfRangeException`** for unknown values — a row with an unexpected locale (blocked by the CHECK constraint) would fail loudly on read rather than map silently.

### `DatabaseOptions.cs`
`sealed class DatabaseOptions { [Required(AllowEmptyStrings = false)] public string ConnectionString { get; set; } = ""; }`. The XML comment says "Bound from configuration key ConnectionStrings:Postgres", but the code *assigns* the captured string in `Configure(...)` rather than binding a section — functionally equivalent here.

### `Interceptors/TimestampInterceptor.cs`
`internal sealed class TimestampInterceptor : SaveChangesInterceptor`. Overrides both sync and async `SavingChanges*`; `Stamp(DbContext?)` null-checks the context, takes one `now` from `IClock`, loops `context.ChangeTracker.Entries()`, and for `Added` entries with a `CreatedAt` property / `Modified` entries with an `UpdatedAt` property writes `entry.Property(name).CurrentValue = now`. Singleton-safe: holds only the clock.

### `MigrationRunner.cs`
`public static async Task ApplyMigrationsAsync(this IServiceProvider, CancellationToken)` — creates an async scope, resolves `AppDbContext`, `Database.MigrateAsync`. Doc comment says "Called by the Api in Development and by the seed command only" — and also by the test fixtures.

### `Schemas.cs`
`internal static class Schemas { Platform = "platform"; Identity = "identity"; }` — `Identity` is unused.

### `UnitOfWork.cs`
Explained in overview §6.7. Fields: `AppDbContext _db`, `IDbContextTransaction? _transaction`. Safe-rollback semantics: `RollbackAsync` clears `_transaction` *before* awaiting rollback so reentrancy cannot double-roll-back; `finally` disposes and `ChangeTracker.Clear()`.

## `Time/SystemClock.cs`
`public sealed class SystemClock : IClock`. `UtcNow => _timeProvider.GetUtcNow()` (so tests can substitute `FakeTimeProvider`). `ToLocal`: `TimeZoneInfo.FindSystemTimeZoneById` + `ConvertTime` → `.DateTime`. `FromLocal`: `DateTime.SpecifyKind(local, Unspecified)`, `zone.GetUtcOffset(wallClock)`, build a `DateTimeOffset` and `.ToUniversalTime()`. Verified by `SystemClockTests`: Cairo 17:00 → 15:00 UTC in January (UTC+2) and 14:00 UTC in July (UTC+3). Edge cases not handled/tested: ambiguous or nonexistent local times around daylight-saving transitions; unknown zone ids throw `TimeZoneNotFoundException`.
