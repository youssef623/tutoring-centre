# .env.example

## Purpose
The committed template for the git-ignored `.env` file that Docker Compose reads. It defines the local PostgreSQL database name, user and (blank) password.

## Where it fits
Local development config. `compose.yaml:5-7,13` reads it. The values must match the connection string set with user-secrets (`README.md:45`).

## Walkthrough
- **Lines 1–2:** instructions. Copy it to `.env`, set a local-only password, and keep DB and USER unchanged because "the API's connection string and the Compose healthcheck use these names".
- **Line 3:** `POSTGRES_DB=tutoring`
- **Line 4:** `POSTGRES_USER=tutoring_dev`
- **Line 5:** `POSTGRES_PASSWORD=` is blank on purpose. `compose.yaml:7` uses `${POSTGRES_PASSWORD:?...}`, so Compose refuses to start until a password is set.

## Concepts used
- **dotenv:** Docker Compose automatically loads `.env` from the project directory for variable substitution.

## Data and control flow
`.env` → Compose variable substitution → container environment → the Postgres image creates the DB and user.

## Configuration and environment
| Variable | Meaning |
| --- | --- |
| `POSTGRES_DB` | database created at first start |
| `POSTGRES_USER` | role created at first start |
| `POSTGRES_PASSWORD` | that role's password (required) |

## Gotchas and issues
- The Postgres image only uses these values when the `pgdata` volume is **empty**. Changing them later needs `docker compose down -v`. This is standard Postgres-image behaviour, not repo code.
- `README.md:27` warns not to put `;` or spaces in the password.
